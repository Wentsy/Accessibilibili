# 評論左右滑流暢度：5666 對照優化，待編譯／實測

使用者回報 5669 分頁恢復可以使用，但左右滑評論比 5666 卡，已在手機
還原 2.1.3+5666（7e5204e）。之前的長串跨頁通過紀錄仍有效，不代表
5669 的流暢度也已驗收。本次不更新穩定基準。

## 本輪只更動原生最後評論查找

5666 與 5669 都在 accessibilityTraits 的 causesPageTurn 判斷中
使用 readingReplies 掃描整個已建立的語義子樹，建立陣列後只取 last。
5669 為了修復暫時底部，讓無剩餘捲動範圍但仍有下一頁時也走這條
路徑，因此此情境比 5666 多了全樹掃描；一般左右滑也可能查詢 traits。
這是可辨識的額外工作，尚無 iPhone profile 證明它是唯一的卡頓原因。

改為反向搜尋子節點、最後檢查父節點，找到第一個符合的評論即返回。
其结果與舊的前序遍歷 last 相同，沒有建立完整評論結果陣列，也不
持久快取節點，避免換頁／排序／進出樓中樓時沿用失效節點。
只有確認是最後一則，才檢查是否還有捲動範圍或 more 標記。
語義子節點陣列的原有取得方式仍保留；本修正並非完全零配置。

保留 5669 的 more/end、邊界載入接續、有限重試、焦點抑制及延後恢復；
不更動 Dart、controller、預載數量、閱讀順序、三指方向或音訊。
所有採用同一原生評論橋接的入口都受益。

## 驗證

`python -m unittest discover -s test -p reply_boundary_search_test.py`
驗證反向查找與原先完整陣列 last 的模型等價，包含隨機巢狀樹、
不同群組、空標籤、追加、移除和重建。500 則平坦模型中，節點造訪
由 502 次降到 3 次；這是模型計數，不是 iPhone 速度或耗時測量。

此環境無 Swift／Xcode／Flutter；Python 模型、語法解析與 diff 檢查
都不代表 Swift 型別檢查或 IPA 編譯通過。本次 Swift 僅使用原檔已有
的 NSObject／UIAccessibilityElement、識別與子節點方法，不新增 SDK API。
Hermes 仍需編譯後交由使用者 A/B 比較。

## 驗收重點

同一影片與同一評論排序，比較 5666 和本版：

1. 連續快速左右滑、往回讀、接近目前已載入底部時的反應。
2. 再用雙指下滑閱讀數百則，確認原本的跨頁卡住沒有復發。
3. 樓中樓、動態等其他評論入口、真正結尾、返回與排序後焦點。

若仍卡頓，下一輪再單獨檢查焦點抑制後補捲動與載入時的 UI 重建，
不將這輪無量測的推論當成根因定論。
