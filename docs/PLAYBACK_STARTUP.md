# 5715 基礎上的開播等待調整

穩定版仍為使用者確認的 2.1.3+5715，程式碼基準為
`efdab3d88fd8f2810e3248269f785018b7e525c6`。本次為待實測候選修改。

## 調查與修改

`VideoDetailController.queryVideoUrl` 原本先等待系統確認 Wi-Fi／行動網路，
以決定畫質、音質與編碼偏好，之後才請求播放網址。播放網址請求本身不使用
這些偏好（請求取得可用格式），所以兩項操作可以重疊進行。

現在同時啟動這兩項操作；兩者完成後才依照原設定挑選畫質、音質、編碼
和固定 CDN。已快取偏好時不重查網路類型。這不是連線測速或線路選擇，
不增加媒體下載請求，也沒有背景輪詢。

另在查詢最外層以 finally 釋放查詢旗標，避免例外讓後續查詢一直被擋住；
非同步結果回來後若頁面已關閉，便不套用結果或啟動播放器。

播放器、預讀容量、分塊補讀、緩衝恢复門檻、鎖屏保護與評論程式均維持 5715。
預期收益限於需要判定網路類型時，把兩段串行等待改為重疊；並非下載頻寬提升，
也不宣稱已有手機秒數改善的量測結果。

兩項非同步錯誤均被接收，並確認沒有額外重試或改寫來源。
已完成修改檔案的 Dart 語法解析與來源差異檢閱。
環境沒有 Flutter／Dart SDK，尚未執行此測試及 IPA 編譯。
Hermes 編譯前可執行 `flutter test test/playback_startup_test.dart`。

手機比較請使用相同影片、固定線路與畫質，確認首次開播、Wi-Fi／行動網路
偏好、切換影片與關閉頁面正常，再評估起播等待是否有可感知的縮短。
