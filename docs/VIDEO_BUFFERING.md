# 影片自動緩衝第一版

目標是減少網路短暫波動時的停頓。這版是有容量上限、隨倍速調整的
預讀策略，尚未根據實際下載速度或卡頓次數學習，也不保證解決解碼或
伺服器斷流造成的停頓。

## 行為

- 播放設定新增預設開啟的「自动缓冲」，不必手動填數字。
- 一般網路影片以 60 秒內容為預讀目標，依 0.5–4 倍速縮放。
- 前向緩衝上限 32 MiB，後向上限 4 MiB；倍速不增加容量上限。
  這是每個 demuxer 的上限，不是整個 App 的記憶體上限；分離的
  DASH 音訊／影片可能各有緩衝，播放器與解碼器也會使用記憶體。
- 停用刻意等緩衝下降後才補讀的 hysteresis，盡量持續補足預讀。
- 耗盡緩衝後，以約 3 秒實際播放量為恢復門檻，隨上述倍速範圍縮放。
  到檔案結尾或容量上限時，mpv 可以提早恢復，不強制等待完整門檻。
- 不要求每次起播或快轉後先等固定緩衝量，以保留操作反應速度。
- 開啟新影片時重新讀取設定；切換倍速／還原倍速也更新當前檔案的緩衝。
- 關閉自動模式後恢復原有手動大小、時間與 1 秒恢復門檻。
- 直播沿用原有容量設定；離線檔案仍使用 `cache=no`。
- 不增加換線、降畫質、降音質、計時器或 VoiceOver 公告。

較多預讀可能增加提早離開影片時未觀看的下載量。網路長期低於影片
所需速率時，有限緩衝仍然會耗盡。

## 實作依據與檢查

依據 [mpv cache 選項](https://mpv.io/manual/stable/#cache) 及
[demuxer 預讀選項](https://mpv.io/manual/stable/#options-demuxer-hysteresis-secs)。
已核對本專案鎖定的 media-kit `version_1.2.5`：`Media.extras` 傳入
loadfile 選項，`Player.setProperty` 為同步 void 方法。倍速更新使用
`file-local-options`，避免將一般影片設定永久套到下一個檔案。

本輪完成 Dart 語法解析、差異空白檢查，以及抽取實際緩衝方法的隔離
Dart 執行檢查：倍速縮放、容量上限、異常速率防護、手動模式還原、
倍速恢復、直播／離線排除。隔離檢查使用假的儲存設定及播放器，
不等同於完整 Flutter 分析或真實 mpv 播放測試。

目前環境沒有 Flutter／Xcode，尚未完成 App 編譯和 iPhone 實測。
Hermes 打包前請執行 Flutter 分析，手機測試請優先使用原本會中斷的影片：

1. 同一網路、同一畫質連續播放，比较自動模式開／關後的停頓頻率。
2. 測試 1 倍、2 倍及還原倍速，確認音訊、畫面和進度正常。
3. VoiceOver 快轉、倒帶、Magic Tap 暫停／繼續後仍能正常操作。
4. 影片接近結尾、換集及切畫質不會卡在緩衝；直播、離線播放正常。

尚未完成實機驗證，不更新無障礙穩定基準。
