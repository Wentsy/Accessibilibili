# 連續閱讀與起播旁白：待實機驗證

## 使用者回報

- 影片起播時，載入／緩衝狀態與影片音訊同時出聲，聽起來互相干擾。
- 雙指下滑從目前位置連續閱讀時，清單讀到一半會停；單指左右滑則能繼續。
- 改善範圍包含整個 App 的清單，不限評論。

## 這版修改

播放器的主要語義節點只追蹤播放／暫停，不再隨短暫緩衝變更 value。
載入圖示、載入文字與持續變動的秒數排除語義，重新載入保留為網路
影片控制的自訂操作。沒有更改 iOS 音訊 session 或系統 VoiceOver
音訊閃避設定；若起播仍有聲音被截斷，需另外診斷音訊 session。

共通 `a11yEnsureVisible` 現在會主動要求畫面更新：單純登記
post-frame callback 不會自行排下一個 frame，靜止畫面的焦點動作
可能因此無法及時帶出後續項目。焦點帶動的捲動預設立即完成，避免
180–220 ms 動畫與連續閱讀競速。保留路由轉場與分頁追加時的焦點
復原抑制；沒有新增朗讀計時器、公告或強制恢復語音。

共用影片卡、UP 影片卡、動態、直播卡與多種收藏原本已使用此 helper。
這版另外接入觀看紀錄、稍後再看、訂閱、收藏夾、UP 收藏夾、影視卡、
搜尋使用者／文章／直播卡及共通 ListTile（多種訊息清單使用）。
這不是對所有頁面已完成實測的宣告；未接入 helper 或使用特殊原生
控制項的畫面仍需依實測補齊。

主評論及樓中樓另增加一個螢幕高度的 layout cache，讀到最後五則時
提前請求下一頁（沿用 controller 的 isLoading／isEnd 防重複保護）。
主評論使用外層穩定 key 與 findChildIndexCallback 保持節點身份。
既有三指翻頁與原生 pageScrolled 回饋保留，沒有把連續閱讀改成
定時三指翻頁。真實列表結尾、網路失敗或使用者中止仍可停止閱讀。

## 驗證狀態

- 修改的 Dart 檔執行語法解析與 git diff 空白檢查。
- 新增 `test/a11y_focus_scroll_test.dart`，涵蓋 idle frame 排程、
  立即捲動、畫面中間項目不移位、分頁抑制與非無障礙模式。
- Flutter 測試環境啟動因嘗試存取雲端 metadata 端點被自動安全審查
  拒絕，未執行 Flutter widget tests／完整 App 分析或 iOS 編譯。
- Hermes 可執行 `flutter test test/a11y_focus_scroll_test.dart`，再編譯 IPA。

## iPhone 優先驗收

1. 開影片時沒有載入圖示／緩衝秒數與影片搶著朗讀；播放、暫停、
   Magic Tap 及自訂「重新載入影片」仍正常。
2. 評論、樓中樓各從中間一則雙指下滑，跨過原本中止的位置及一次
   資料分頁；沒有跳回第一則或漏掉下一則。
3. 推薦、動態、UP 影片、觀看紀錄、稍後再看、收藏、訂閱、搜尋、
   訊息清單同樣測試連續閱讀。記錄仍會停下的具體頁面與位置。
4. 手動停止後保持安靜；單指左右滑及三指翻頁仍正常。
5. 從詳情返回、排序或載入下一頁後，焦點／畫面不跳頂。

尚未通過上述測試，不更新目前已驗證的無障礙基準。
