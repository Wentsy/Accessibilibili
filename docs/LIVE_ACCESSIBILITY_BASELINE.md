# Accessibilibili 直播 VoiceOver 無障礙基準

這份文件專門記錄直播相關的 VoiceOver 行為，避免未來同步 PiliPlus 官方更新時，只驗收一般影片與評論，卻讓直播頁重新退化。

狀態：**部分已完成 VoiceOver 實機驗證；未驗證的新項目仍須以實機結果為準。**

目前實機紀錄：

- `Accessibilibili_ios_2.1.3+5448.ipa`
  - 直播推薦頁「一滑一個直播」：已通過。
  - 直播貼圖面板完整 VoiceOver 支援：已通過。
  - 直播聊天室彈幕「一滑一條完整訊息」：已通過。
  - 一般彈幕與回覆彈幕朗讀格式：已通過。
  - 彈幕內貼圖／表情朗讀：已通過。
- `Accessibilibili_ios_2.1.3+5452.ipa`
  - 新彈幕不搶焦點：**未通過**。閱讀舊彈幕時仍可能被強制帶回列表頂部／失去目前閱讀位置。
  - 三指翻頁：**部分通過**。VoiceOver 焦點位於彈幕區時可正常翻頁；焦點位於「發送彈幕」或直播頁其他非彈幕控制時，三指上下只出現邊界音效，沒有移動彈幕列表。
  - 頂端再三指向下刷新：**未通過／無法確認刷新是否發生**。沒有聽到「正在重新整理彈幕」或完成提示。
  - 彈幕不要求增加時間戳；目前問題是焦點、翻頁作用範圍與刷新回饋，不是時間資訊。
- 針對 5452 實測問題，`83405b0`、`042ac4e`、`096ae03` 已重新調整 VoiceOver 暫停狀態、焦點穩定 key 與整頁三指翻頁作用範圍；須由下一個 IPA 再實機驗證。`5a79a0b` 僅恢復一次無關的直播分享 `authorID`，不屬於無障礙功能變更。

## 1. 直播推薦卡：一滑一個直播

重點檔案：

```text
lib/pages/live/widgets/live_item_app.dart
```

VoiceOver 左右滑動時，一張直播推薦卡應是一個完整語義節點，不應把封面、觀看數、標題、主播與右下角「更多」拆成多個焦點。

建議朗讀資訊順序：

```text
直播標題，主播，分區，觀看資訊
```

必要規則：

- 一次右滑從上一個直播直接進入下一個直播。
- 不應在兩張直播之間額外遇到一顆「更多」按鈕。
- 視覺上的更多按鈕仍保留給一般觸控使用者。
- VoiceOver 的「更多操作」改由該直播卡的 `CustomSemanticsAction` 提供。
- 點兩下直播卡仍進入原本的直播間。
- VoiceOver 聚焦直播卡時，真實 viewport 應保持與焦點同步。
- 沒有 feedback／更多資料的直播卡，不應虛構「更多操作」。

### 驗收

- [x] 直播推薦頁每次左右滑只移動一張直播卡。
- [x] 標題、主播、分區、觀看資訊會一次朗讀。
- [x] 兩張直播卡之間不再出現獨立「更多」焦點。
- [ ] 有更多操作的直播卡可透過 VoiceOver 自訂操作找到「更多操作」。
- [ ] 執行「更多操作」後仍打開原本的 feedback 對話框。
- [x] 點兩下直播卡可正常進入直播間。
- [x] 連續瀏覽時畫面會跟著 VoiceOver 焦點移動。

## 2. 直播聊天的表情／貼圖入口

重點檔案：

```text
lib/pages/live_room/send_danmaku/view.dart
```

直播彈幕輸入列的笑臉 icon 不能只是一張沒有名稱的圖示。

必要規則：

- 貼圖面板關閉時，按鈕朗讀為「表情與貼圖」。
- 提示為「點兩下選擇表情與貼圖」。
- 貼圖面板開啟後，同一位置應改成「鍵盤」。
- 提示為「點兩下返回鍵盤」。
- 視覺點擊與 VoiceOver `onTap` 必須共用同一個切換 callback。

### 驗收

- [x] 打開直播彈幕輸入介面可以找到「表情與貼圖」按鈕。
- [x] 點兩下能正常打開直播貼圖面板。
- [x] 面板打開後按鈕會改念「鍵盤」。
- [x] 點兩下「鍵盤」可正常回到文字鍵盤。

## 3. 直播貼圖本身必須可朗讀、可操作

重點檔案：

```text
lib/pages/live_emote/view.dart
```

每一張可插入或直接送出的直播貼圖都必須是一個穩定的 VoiceOver 按鈕節點。

標籤來源：

1. 優先使用 API 的 `emoji` 名稱。
2. 去掉最外層的 `[`、`]` 後朗讀，例如 `打招呼 貼圖`。
3. 名稱不存在時至少朗讀「貼圖」。

必要規則：

- 貼圖圖片本身不要額外搶焦點。
- `pkgType == 3` 的貼圖提示「點兩下插入這個貼圖」。
- 其他直接送出的貼圖提示「點兩下送出這個貼圖」。
- VoiceOver `onTap` 與原本 InkWell 共用同一個 `choose()` callback。
- 插入後可朗讀「已插入○○貼圖」。
- 直接送出後可朗讀「已送出○○貼圖」。
- VoiceOver 左右移動貼圖焦點時，實際 Grid viewport 應同步跟著移動，不能讓焦點跑到畫面外。

### 驗收

- [x] 左右滑可以逐張找到貼圖，不再只遇到無名稱圖片。
- [x] 有名稱的貼圖會念出名稱與「貼圖」。
- [x] 沒名稱時至少會念「貼圖」。
- [x] 點兩下插入型貼圖能正常出現在輸入框。
- [x] 點兩下直接送出型貼圖仍能正常送出。
- [x] 插入／送出後有簡短 VoiceOver 回饋。
- [x] 連續瀏覽貼圖時實際畫面會跟著 VoiceOver 焦點移動。

## 4. 直播貼圖包分組 Tab

目前直播貼圖資料模型只有 `currentCover` 與類型，沒有可靠的分組名稱，因此不要自行猜測名稱。

目前統一使用：

```text
貼圖包第1組
貼圖包第2組
……
```

必要規則：

- 分組 Tab 必須保留 TabBar 原本的可切換語義。
- 不要為了隱藏封面圖片而把 TabBar 自己的點兩下操作一起排除。
- 不要在分組 Tab 外層加入會吃掉 TabBar 語義的 `excludeSemantics: true`。
- 如果未來 API 增加可靠分組名稱，可優先改成真正名稱。

### 驗收

- [x] VoiceOver 可辨識每個貼圖包分組。
- [x] 點兩下分組後能正常切換貼圖內容。
- [x] 分組封面圖片不會額外形成重複焦點。

## 5. 圖示型快速控制：不能只念「按鈕」或圖像描述

重點檔案：

```text
lib/pages/live_room/view.dart
lib/pages/live_room/send_danmaku/view.dart
```

直播頁存在很多只用 icon 呈現的快速操作。對 VoiceOver 而言，「按鈕」或「笑臉圖」只能算半張標籤，仍不足以讓使用者知道按下去會做什麼。

必要規則：

- 所有可互動 icon-only 控制都必須有明確、可理解的名稱。
- 名稱應描述「功能」，而不是描述圖案外觀。
- 例如笑臉圖示應朗讀「快速發送貼圖」或「表情與貼圖」，不能只依賴 VoiceOver 自動辨識成「笑臉圖」。
- 彈幕顯示切換應依目前狀態朗讀「開啟彈幕顯示」／「關閉彈幕顯示」。
- 動態切換功能的名稱必須反映「下一步會做什麼」，不要只念目前狀態。
- 新增直播控制時，不可只檢查是否有 button trait；必須實際確認 VoiceOver 能說出用途。

目前明確要求：

```text
快速發送貼圖
開啟彈幕顯示
關閉彈幕顯示
表情與貼圖
鍵盤
```

### 驗收

- [ ] 最外層「快速發送貼圖」不再只念「按鈕」或「笑臉圖」。
- [ ] 彈幕顯示開關會依目前狀態朗讀「開啟彈幕顯示」或「關閉彈幕顯示」。
- [ ] 同一列其他 icon-only 控制不存在只有「按鈕」而沒有用途名稱的項目。

## 6. 直播彈幕：一滑一條完整訊息

重點檔案：

```text
lib/pages/live_room/widgets/chat_panel.dart
```

直播彈幕具有即時性，但單條訊息的 VoiceOver 語義仍應比照評論區：「一個邏輯單位只佔一個焦點」。

必要規則：

- 一條彈幕是一個完整 VoiceOver semantic node。
- 一般彈幕朗讀：`某某 說：內容`。
- 回覆彈幕朗讀：`某某 回覆 某某：內容`。
- 訊息中的表情／貼圖不能只暴露圖片；應把可取得的貼圖名稱轉成文字，例如 `doge 貼圖`。
- 點兩下可回覆可互動的彈幕。
- 可提供 `回覆這條彈幕`、`造訪使用者`、`更多操作` 等 CustomSemanticsAction。
- 不要把使用者名稱、回覆對象、文字內容、貼圖拆成多個左右滑焦點。
- VoiceOver 聚焦某條彈幕時，實際 viewport 應同步到該條訊息。

### 即時訊息特別規則

- VoiceOver 一旦開始閱讀彈幕，應進入獨立的無障礙閱讀暫停狀態；一般 ScrollController listener 不得自行解除這個狀態。
- 新彈幕可以繼續接收，但應暫存在佇列／未顯示批次，讓目前閱讀中的列表與語義焦點保持穩定。
- 使用者走到目前可見的最新訊息時，可以揭露累積的新彈幕，但揭露後原本聚焦的訊息必須靠穩定 key 保持原焦點，不得跳回列表頂部。
- 不應要求 VoiceOver 使用者一定要尋找額外的「回到底部」按鈕才能恢復閱讀；單指左右或三指翻頁應足以完成移動。
- 非 VoiceOver 使用者原本的「回到底部」介面可以保留，不需為無障礙需求破壞一般操作。

### 驗收

- [x] 左右滑一次只讀一條完整彈幕。
- [x] 一般彈幕與回覆彈幕朗讀格式正確。
- [x] 彈幕內的貼圖／表情有文字名稱或「貼圖」fallback。
- [ ] 往回讀舊彈幕時，新彈幕進來不會搶焦點、把畫面拉走或把焦點重設到列表頂部。
- [ ] 單指一路往新訊息方向閱讀，可以揭露並接上累積的新彈幕，同時保住目前焦點。
- [ ] VoiceOver 模式不需要依賴「回到底部」按鈕。

## 7. 直播彈幕三指翻頁與頂端刷新

重點檔案：

```text
lib/common/a11y/voiceover_paged_scroll.dart
lib/pages/live_room/widgets/chat_panel.dart
lib/pages/live_room/view.dart
```

直播彈幕區應接入 Accessibilibili 已有的三指上下翻頁系統，不要另造一套速度與手勢不同的聊天室翻頁。

必要規則：

- 三指向上：往較新的彈幕方向翻一頁。
- 三指向下：往較舊的彈幕方向翻一頁。
- 翻頁沿用全域 `VoiceOverPagedScroll` 的頁幅、動畫時間與 iOS `pageScrolled` 回饋。
- 目前主翻頁體感基準仍約為 `0.85 viewport / 160ms / easeOutCubic`。
- 三指翻頁的語義作用範圍必須涵蓋整個非全螢幕直播觀看頁；VoiceOver 焦點即使位於「發送彈幕」、快速控制、主播資訊或其他非彈幕控制，三指上下仍應操作彈幕 ScrollController。
- 彈幕列表本身仍可保留自己的翻頁語義，確保焦點位於列表內時的邊界 callback 正常。
- 在彈幕區已經到最前端時，再做一次三指向下，可以觸發「重新整理彈幕」。
- 這個刷新只重新抓直播彈幕歷史，不重載播放器；不需要為此新增彈幕時間戳。
- 刷新開始、完成或失敗都要有可被 VoiceOver 實際聽到的公告，例如「正在重新整理彈幕」與「彈幕已重新整理」。
- 到達較新方向邊界時，可以揭露排隊的新訊息，但不得因此解除 VoiceOver 閱讀暫停或搶走焦點。

### 驗收

- [ ] VoiceOver 焦點在彈幕內時，三指向上／向下可正常翻頁。
- [ ] VoiceOver 焦點在「發送彈幕」或直播頁其他非彈幕控制時，三指向上／向下仍可翻動彈幕列表。
- [ ] 翻頁速度與其他已驗證列表一致，並有原生 VoiceOver 翻頁回饋。
- [ ] 到第一頁後再三指向下會重新整理彈幕。
- [ ] 重新整理彈幕時直播聲音／播放器不中斷。
- [ ] 刷新有可實際聽到的「正在重新整理彈幕」與完成／失敗回饋。
- [ ] 到較新方向邊界後能揭露累積的新彈幕且焦點保持穩定。

## 8. 與既有全域無障礙機制的關係

直播修正不得破壞既有成熟功能：

- VoiceOver 三指上下翻頁與原生 `pageScrolled` 回饋。
- 焦點與真實 viewport 同步。
- 一般首頁影片卡的一滑一整條。
- 主評論／樓中樓的一滑一整條。
- 播放器進度 ±10 秒與 Magic Tap。

未來如果上游重寫 `lib/pages/live/`、`lib/pages/live_room/`、`lib/pages/live_emote/` 或全域 `VoiceOverPagedScroll`，應重新跑本文件全部項目。

## 9. 完整直播快速驗收

同步官方版或修改直播功能後，至少跑一次：

- [ ] 進入首頁的直播分頁。
- [ ] 連續右滑 10 張直播卡，確認一滑一張且沒有獨立更多焦點。
- [ ] 任選有 feedback 的直播卡測試「更多操作」。
- [ ] 點兩下進入直播間。
- [ ] 檢查最外層快速控制，不能出現只有「按鈕」而沒有用途名稱的 icon-only 控制。
- [ ] 確認「快速發送貼圖」與「開啟／關閉彈幕顯示」名稱正確。
- [ ] 打開彈幕輸入介面。
- [ ] 找到「表情與貼圖」並打開。
- [ ] 左右滑至少 10 張貼圖，確認都有名稱或「貼圖」fallback。
- [ ] 實際插入一張普通貼圖。
- [ ] 若有直接送出型貼圖，實際送出一張。
- [ ] 切換至少兩個「貼圖包第 N 組」。
- [ ] 點「鍵盤」返回文字輸入。
- [ ] 在聊天室左右滑至少 10 條彈幕，確認一滑一條完整訊息。
- [ ] 停在舊彈幕數秒，確認新訊息進來不會搶焦點、拉走畫面或把焦點重設到頂部。
- [ ] 在彈幕內三指上下翻頁。
- [ ] 把 VoiceOver 焦點移到「發送彈幕」與其他直播控制，再測三指上下，確認仍翻動彈幕。
- [ ] 到彈幕第一頁後再三指向下，確認可重新整理彈幕、聽到刷新公告且直播不中斷。
- [ ] 確認 VoiceOver 模式不依賴「回到底部」按鈕也能接上最新訊息。
- [ ] 回到直播推薦頁，再確認三指翻頁與 VoiceOver 原生翻頁音效沒有退化。

只有完成對應項目的實機測試後，才把該項目標成已驗證穩定。不要因為程式能編譯就直接視為 VoiceOver 驗收通過。
