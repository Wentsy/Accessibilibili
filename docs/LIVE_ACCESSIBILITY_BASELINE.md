# Accessibilibili 直播 VoiceOver 無障礙基準

這份文件是 Accessibilibili 直播相關 VoiceOver 行為的**穩定基準**。未來同步 PiliPlus 官方更新、重構直播頁或修改共用無障礙元件時，應保留本文件描述的使用體驗，而不是只保留某一段舊程式碼。

狀態：**2026-09-03 已完成核心直播流程 VoiceOver 實機驗收，可作為穩定基準。**

本文件與以下文件一起使用：

- `docs/ACCESSIBILITY_MAINTENANCE.md`：上游同步流程與整體驗收。
- `docs/VOICEOVER_SEMANTICS_BASELINE.md`：全域「一滑一整條」與貼圖／表情語義原則。
- `docs/UPSTREAM_ACCESSIBILITY_AUDIT.md`：Accessibilibili 相對 PiliPlus 官方版的重要無障礙差異。

## 0. 已驗證版本與重要里程碑

### `Accessibilibili_ios_2.1.3+5448.ipa`

實機確認：

- 直播推薦頁「一滑一個直播」通過。
- 直播貼圖面板完整 VoiceOver 支援通過。
- 直播聊天室「一滑一條完整彈幕」通過。
- 一般彈幕與回覆彈幕朗讀格式通過。
- 彈幕內貼圖／表情朗讀通過。

### `Accessibilibili_ios_2.1.3+5452.ipa`

這一版曾暴露三個 regression，**不能視為最終穩定行為**：

- 讀舊彈幕時，新彈幕可能把 VoiceOver 焦點／畫面帶走。
- 三指翻頁只有焦點在彈幕區時有效；焦點在發送按鈕或直播頁其他控制時無效。
- 當時把列表方向判反，錯把最舊端當成最新端，因此刷新邊界設計錯誤。

後續已針對這些實測問題修正，並於 2026-09-03 再次實機驗收通過。

### 2026-09-03 穩定基準

目前穩定行為包含：

- 舊彈幕閱讀時，新彈幕不搶焦點、不強制捲動。
- 三指翻頁在整個非全螢幕直播觀看頁有效，不只彈幕列表本身。
- 彈幕列表方向已確認：**上方較舊、下方較新**。
- 三指向上往較新彈幕翻；到最新端再向上可更新至最新／重新抓取最新彈幕。
- 三指向下往較舊彈幕翻；到最舊端再向下只提示已到最舊，不觸發刷新。
- 「回到底部」重新保留給 VoiceOver，作為快速回到最新彈幕的明確操作。
- 每條彈幕朗讀精確到秒的發送時間，時間位於最後。
- 小時用「點」而不是「時」，例如 `今天1點13分45秒發送`，避免高語速下「一時十三分」黏音誤聽。

相關穩定修正包含：

```text
83405b0  VoiceOver 閱讀暫停不再被一般 scroll listener 解除
042ac4e  穩定彈幕 semantic key 與排隊訊息揭露
096ae03  三指翻頁作用範圍提升到整個直播觀看頁
0f6ddf1  刷新／更新行為改到最新彈幕邊界
5c1bef7  彈幕秒級時間與 VoiceOver「回到底部」恢復
bd7fc51  彈幕時間「時」改為「點」以改善快速朗讀辨識
```

`5a79a0b` 只恢復一次無關的直播分享 `authorID`，不是無障礙功能基準的一部分。

## 1. 直播推薦卡：一滑一個直播

重點檔案：

```text
lib/pages/live/widgets/live_item_app.dart
```

VoiceOver 左右滑動時，一張直播推薦卡是一個完整語義節點，不應把封面、觀看數、標題、主播與右下角「更多」拆成多個焦點。

建議朗讀順序：

```text
直播標題，主播，分區，觀看資訊
```

必要規則：

- 一次右滑直接從上一張直播卡移到下一張。
- 視覺封面、Badge、觀看圖示與右下角更多按鈕不得額外形成無意義焦點。
- 點兩下直播卡仍進入原本直播間。
- VoiceOver 聚焦卡片時，真實 viewport 與焦點同步。
- 視覺上的「更多」可保留給一般觸控；VoiceOver 額外操作優先使用 `CustomSemanticsAction`。
- 沒有 feedback／更多資料時，不應虛構「更多操作」。

- [x] 標題、主播、分區、觀看資訊一次朗讀。
- [x] 兩張卡之間沒有獨立「更多」焦點。

## 3. 直播貼圖：每張都是可理解、可操作的語義節點

```text

```

每一張貼圖應：

- 是一個穩定的 VoiceOver 按鈕節點。

- VoiceOver `onTap` 與視覺點擊共用同一個 `choose()` callback。
- 插入／送出後有簡短 VoiceOver 回饋。
- 左右移動焦點時，Grid 真實 viewport 同步跟著移動。
- lazy grid rebuild 不得把焦點跳回第一張。

## 5. 直播彈幕：一滑一條完整訊息

重點檔案：

```text
lib/pages/live_room/widgets/chat_panel.dart
```

直播彈幕沿用評論區核心原則：**一個邏輯內容單位只佔一個 VoiceOver 焦點。**

### 朗讀格式

一般彈幕：

```text
某某 說：內容，今天1點23分45秒發送
```

回覆彈幕：

```text
某某 回覆 某某：內容，今天1點23分45秒發送
```

時間資料無效或不存在時可省略時間，不得猜測。

### 時間規則

- 使用直播彈幕 `extra.ts` 的 UNIX 秒級時間戳。
- 保留到秒，不降成只有「幾分鐘前」。
- 時間永遠放在內容最後。
- 同日：`今天1點23分45秒發送`。
- 昨日：`昨天23點58分12秒發送`。
- 同年較早日期：`9月2日23點58分12秒發送`。
- 跨年：`2025年12月31日23點58分12秒發送`。
- 小時一律用「點」，不用「時」，降低高語速下黏音誤聽。

### 貼圖／表情

- 內嵌表情或貼圖不得只暴露圖片。
- 有名稱時把名稱轉成文字，例如 `doge 貼圖`。
- 無名稱時至少用「貼圖」fallback。

### 操作

- 點兩下可回覆可互動的彈幕。
- 可提供 `回覆這條彈幕`、`造訪使用者`、`更多操作` 等 `CustomSemanticsAction`。
- 使用者名稱、回覆對象、文字、貼圖與時間都屬於同一條彈幕語義，不拆成多個左右滑焦點。
- 聚焦某條彈幕時，真實 viewport 應同步到該訊息。

### 已驗收

- [x] 一滑一條完整彈幕。
- [x] 一般與回覆格式正確。
- [x] 內嵌貼圖／表情可朗讀。
- [x] 精確時間位於最後並朗讀到秒。
- [x] 「時」已改為「點」，實機確認朗讀正確。

## 6. 即時新彈幕：閱讀舊訊息時不得搶焦點

重點檔案：

```text
lib/pages/live_room/controller.dart
lib/pages/live_room/widgets/chat_panel.dart
```

這是直播聊天室最重要的穩定行為之一。

### 核心狀態

VoiceOver 開始閱讀聊天室後，使用獨立的無障礙閱讀暫停狀態（目前為 `a11yChatPaused`）。它與一般觸控／ScrollController 的 `disableAutoScroll` 不可混為同一件事。

必要規則：

- VoiceOver 聚焦彈幕後可暫停直播列表的自動跟隨。
- 一般 `scrollController.listener()` 不得自行解除 VoiceOver 的閱讀暫停。
- 新彈幕仍可接收，但先排入未顯示批次，不立即 rebuild 畫面。
- 新彈幕進來時不得把 VoiceOver 焦點或 viewport 強制拉到底部或列表頂部。
- 排隊內容揭露時，既有彈幕使用穩定 semantic key，避免 rebuild 後焦點跳回第一條。
- 單指一路讀到目前可見最新訊息時，可以悄悄揭露排隊內容，但**不得因揭露就強制跳到底部**。
- 使用者主動要求回到最新內容時，才可以解除暫停並跳到最新端。

### 已驗收

- [x] 停在舊彈幕時，新彈幕不搶焦點。
- [x] 新彈幕不再把畫面強制拉走。
- [x] 排隊內容揭露後焦點保持穩定。
- [x] 單指閱讀可以繼續銜接後續彈幕。

## 7. 三指翻頁：作用於整個直播觀看頁

重點檔案：

```text
lib/common/a11y/voiceover_paged_scroll.dart
lib/pages/live_room/widgets/chat_panel.dart
lib/pages/live_room/view.dart
```

### 列表方向（非常重要）

直播聊天室目前的實際方向是：

```text
上方 = 較舊彈幕
下方 = 較新彈幕
```

不要再把最上方誤認為最新訊息。

### 手勢方向

- **三指向上**：往較新的彈幕方向翻一頁，也就是往列表下方移動。
- **三指向下**：往較舊的彈幕方向翻一頁，也就是往列表上方移動。

翻頁沿用全域 `VoiceOverPagedScroll` 體感基準：

```text
約 0.85 viewport / 160ms / easeOutCubic
```

並保留 iOS 原生 `pageScrolled` 回饋。

### 作用範圍

VoiceOver 的三指翻頁不能只在聊天室 ListView 本身有效。

整個**非全螢幕直播觀看頁**都應掛到同一個聊天室 ScrollController，因此焦點即使位於：

- 發送彈幕按鈕
- 快速貼圖
- 彈幕顯示開關
- 主播資訊
- 其他直播控制

三指上下仍應翻動聊天室。

### 已驗收

- [x] 焦點在彈幕內時可三指上下翻頁。
- [x] 焦點在發送彈幕或其他非彈幕控制時仍可翻頁。
- [x] 翻頁方向符合「上舊、下新」。
- [x] 原生翻頁回饋正常。

## 8. 最新端更新／刷新與最舊端邊界

### 最舊端

當已經位於最舊彈幕端（列表頂部）後再三指向下：

- **不刷新聊天室**。
- 提示：`已到最舊彈幕`。

### 最新端

當已經位於最新端（列表底部）後再三指向上：

1. 如果有排隊的新彈幕：
   - 揭露排隊內容。
   - 解除 VoiceOver 閱讀暫停。
   - 回到列表底部。
   - 提示：`已更新至最新彈幕`。
2. 如果沒有排隊內容：
   - 重新抓取最新彈幕快照。
   - 暫時關閉直播訊息 websocket，避免刷新快照與新訊息同時覆寫。
   - 不重新載入播放器／直播串流。
   - 開始時提示：`正在重新整理彈幕`。
   - 成功後回到底部並提示：`彈幕已重新整理`。
   - 失敗提示：`彈幕重新整理失敗`，並恢復原本閱讀狀態。

### 已驗收

- [x] 最新端再三指向上可更新／刷新。
- [x] 刷新有明確 VoiceOver 語音提示。
- [x] 刷新時直播播放不中斷。
- [x] 最舊端再三指向下不會誤觸刷新。

## 9. 「回到底部」是 VoiceOver 可用的快速回最新功能

「回到底部」原本就是上游介面，不是 Accessibilibili 新造的按鈕。

早期因新彈幕會把焦點拉走，曾一度把它在 VoiceOver 模式隱藏；實機驗證後確認，當「新彈幕不搶焦點」已修好，這顆按鈕反而很有價值，因此**應保留給 VoiceOver 使用者**。

必要行為：

- VoiceOver 可聚焦「回到底部」。
- 點兩下後解除 `a11yChatPaused`。
- 揭露排隊的新彈幕。
- 跳到聊天室 `maxScrollExtent`，也就是最新訊息端。
- 這是快速捷徑，不是唯一回到最新內容的方法；三指向上與單指閱讀仍應可正常工作。

### 已驗收

- [x] VoiceOver 可使用「回到底部」。
- [x] 不再因新彈幕搶焦點而把它誤判為無用功能。

## 10. 觀看紀錄中的已下播直播

重點檔案：

```text
lib/pages/history/widgets/item.dart
```

觀看紀錄可能保留已下播的直播項目。這些項目如果只在點兩下後嘗試用 `SemanticsService.announce()` 提示，實機上公告可能被後續 semantics／焦點事件立即中斷，只聽到第一個字。因此穩定基準不是依賴「點擊後額外 announce」，而是**把直播狀態直接放進卡片原本的完整語義**。

未開播直播應直接朗讀，例如：

```text
直播標題，主播，昨天看過，主播目前未開播
```

必要規則：

- `business == 'live' && liveStatus != 1` 時，在卡片 label 最後加入「主播目前未開播」。
- 未開播直播的 hint 不應再說「點兩下繼續觀看」，避免提供不存在的操作承諾。
- VoiceOver 模式不依賴點擊後 announce。
- 一般非 VoiceOver 模式仍可在點擊時保留視覺 Toast。
- 正在直播的紀錄仍可正常點兩下進直播間。

### 已驗收

- [x] 左右滑到已下播直播時，卡片本身會完整朗讀「主播目前未開播」。
- [x] 不需要點兩下才知道為什麼打不開。
- [x] 不再依賴會被中斷的額外 announce。


- [ ] 點兩下可正常進直播間。

### 快速控制與輸入

- [ ] 「快速發送貼圖」名稱正確。
- [ ] 彈幕顯示切換朗讀「開啟彈幕顯示」／「關閉彈幕顯示」。
- [ ] 打開彈幕輸入後可找到「表情與貼圖」。
- [ ] 面板打開後入口改念「鍵盤」。

### 貼圖

- [ ] 左右滑至少 10 張貼圖，每張都有名稱或「貼圖」fallback。
- [ ] 插入型貼圖可正常插入並有回饋。
- [ ] 直接送出型貼圖可正常送出並有回饋。
- [ ] Grid viewport 跟著 VoiceOver 焦點移動。
- [ ] 至少切換兩個貼圖包分組，Tab 可朗讀、可點兩下。

### 彈幕語義與時間

- [ ] 左右滑至少 10 條彈幕，一滑一條完整訊息。
- [ ] 一般／回覆格式正確。
- [ ] 內嵌貼圖／表情有文字名稱。
- [ ] 時間位於最後並精確到秒。
- [ ] 小時朗讀用「點」，例如 `1點13分45秒`。

### 即時焦點

- [ ] 停在舊彈幕數秒，新訊息不搶焦點、不拉走畫面。
- [ ] 單指往新訊息方向閱讀，可接上排隊內容且焦點不跳回第一條。

### 三指翻頁與邊界

- [ ] 焦點在彈幕內，三指向下往舊、三指向上往新。
- [ ] 焦點移到「發送彈幕」或其他直播控制，三指仍操作聊天室。
- [ ] 到最舊端再三指向下只聽到「已到最舊彈幕」。
- [ ] 到最新端再三指向上可更新／刷新並聽到明確公告。
- [ ] 刷新期間播放器不中斷。
- [ ] 「回到底部」可由 VoiceOver 找到並回到最新端。

### 觀看紀錄直播狀態

- [ ] 找一筆已下播直播紀錄，左右滑聚焦時直接聽到「主播目前未開播」。
- [ ] 未開播項目不再提示「點兩下繼續觀看」。
- [ ] 正在直播的紀錄仍可正常開啟。
