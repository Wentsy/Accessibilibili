# 固定線路直播緩衝與重連候選修正

## 修改

- 直播仍使用使用者選定的 URL，不探測或切換線路。
- 原本每次匹配到網路錯誤就獨立安排 3 秒後重開。現在同時只允許一個
  待執行或執行中的重連，合併錯誤爆發，不讓多次重開互相打斷。
- 偵測到未緩衝、播放位置前進且緩衝終點超過出錯時的位置才取消待執行重連；
  避免只是在播放既有快取就誤認下載恢復。不只憑 buffering=false
  判定恢復，避免失敗／結束事件誤取消必要重試。
- 手動暫停、換來源或播放器釋放時取消待執行任務並使舊任務失效。
  已開始的 open 無法強制撤回，但先以 play=false 重開，在確認播放意圖及
  來源仍有效後才恢復播放；換來源前會等待已開始的重開操作結束。
- 重新開啟原 live Media，保留 URL 與參數，不帶入上次的已播放時間。
- 重開例外會被接收；只有後續串流錯誤會觸發新嘗試，沒有無條件重試迴圈。
- 直播專用預讀目標 6 秒、持續補讀、耗盡後約補 2 秒再恢復；起播不強制
  等滿緩衝，記憶體容量上限沿用原設定。這不是新增固定 6 秒延遲，實際
  可緩衝量仍受伺服器供應、串流格式與容量限制；直播延遲需實測。

一般影片的開播並行優化、固定線路、緩衝參數及評論程式不變。
本修正不處理伺服器斷流、網址過期或來源長期頻寬不足等所有原因。

## 驗證狀態

已完成 Dart 語法解析與差異檢閱。新增
`test/live_reconnect_scheduler_test.dart` 覆蓋錯誤合併、取消待執行任務、
重開中暫停、例外釋放及沒有無限重试的情境。

環境無 Flutter／Dart SDK，尚未執行測試、IPA 編譯或手機直播實測。
Hermes 可執行 `flutter test test/live_reconnect_scheduler_test.dart` 後編譯。
手機重點確認：短暫網路波動後是否少了連續重開、手動暫停不被舊任務恢復、
切換直播間不串台，以及續播平順程度與直播延遲。此候選版不更新穩定基準。
